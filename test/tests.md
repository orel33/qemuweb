# Tests

Run commands from the repository root. `./scripts/run-tests.sh --list` shows the available scenarios and prints a short reminder when one starts. `npm test` selects only `test/unit/*.test.js`; the integration scripts must be run explicitly. The integration tests start their own QemuWeb server and guests, then remove the hosts and switches they created.

## Integration tests (`test/integration/`)

Every scenario logs in for real: `qemuweb-client.js` writes a temporary users file with random passwords, starts the server with `--users` (and `--ephemeral`, `--logs` where a scenario reads the logs), and drives it with an HTTP and Socket.IO client that keeps the session cookie like a browser. The server has no test backdoor.

These scenarios require QEMU and prepared RAW images. The two-hosts-stop-resume, four-hosts, check-load-start and check-network scenarios require a QEMU build with VDE support, the VDE tools and QEMU/KVM (`/dev/kvm`).

## Manual tests of the Web interface

`./scripts/demo.sh` starts the application on port 3003 (`--listen PORT` changes it) for manual tests in a browser. It never reads or changes the repository's `users.json`: it writes a separate, temporary users file (`--users`) with three accounts, and deletes it when the application stops (Ctrl+C or TERM). The server runs from the project root, so `./scripts/stop.sh` (with the same `--listen`) and `./scripts/status.sh` find it:

| Login | Password | Role | Session at start |
|---|---|---|---|
| `admin` | `admin` | admin | empty |
| `toto` | `toto` | student | `demo/lan.zip` loaded and started |
| `tutu` | `tutu` | student | `demo/lan.zip` loaded and started |

Passwords equal to logins exist only in this demo mode. After the server is up, `scripts/demo.js` logs in as `toto` and `tutu` and loads `demo/lan.zip` with automatic start, exactly like the **Load session** button; start errors are printed without stopping the demo. Memory: 2 sessions x (1 switch + 4 hosts) start at once, about 8 GiB of guest memory, and QEMU/KVM and VDE are needed. The script stops with a message before starting the server when the archive or a base image it needs (`images/debian13-legacy.raw`) is missing. Logs go to `logs/` as usual.

Check isolation by logging in as `toto` and `tutu` in two browsers (or a private window). For the admin role, log in as a student in one browser and as `admin` in another: open **Supervision**, **Observe** the student, check that the banner, the follow-node behaviour and **Take control** work on both sides, then try **Stop all** and **Resume all**, **Delete** and the account actions, and read the **Logs** panel (`logs/admin.log`, `logs/users.log`).
