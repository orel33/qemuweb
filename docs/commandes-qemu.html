Commandes QEMU : QemuNet historique et démo web

Commande complète fournie par Orel · xterm + QEMU · VM « grave » · Debian 10

xterm \
Option de la commande historiqueFonction / remarque
-fg white \Texte blanc dans xterm.
-bg black \Fond noir dans xterm.
-T grave \Titre de la fenêtre xterm.
-e qemu-system-x86_64 \Lance QEMU comme programme interactif dans le pseudo-terminal d’xterm.
-name grave \Nom de la VM dans QEMU ; ne change pas le hostname de l’invité.
-rtc base=localtime \Initialise l’horloge matérielle virtuelle à l’heure locale.
-k fr \Clavier graphique QEMU ; n’agit normalement pas sur cette console série dans xterm.
-M accel=kvm \Accélération KVM ; modèle de machine laissé au défaut de QEMU.
-m 200 \200 Mio de mémoire vive.
-drive file=/tmp/qemunet-orel-OgwDNU/grave.qcow2,format=qcow2,index=0,media=disk \Premier disque QCOW2 ; bus IDE implicite sur ce PC QEMU.
-fsdev local,id=share0,path=/tmp/qemunet-orel-OgwDNU/grave,security_model=mapped \Déclare le répertoire partagé côté hôte et son modèle de permissions.
-device virtio-9p-pci,fsdev=share0,mount_tag=host \Expose ce répertoire à l’invité via virtio-9p, sous le tag « host ».
-netdev vde,sock=/tmp/qemunet-orel-OgwDNU/switch/s1,port=4,id=s1 \Connecte la VM au port 4 du switch VDE « s1 ».
-device e1000,netdev=s1,mac=AA:AA:AA:AA:03:00 \Carte réseau e1000 liée à s1 ; adresse MAC fixée.
-kernel /home/orel/Documents/projet-qemunet/qemunet/images/debian10.vmlinuz \Charge directement ce noyau Linux, sans passer par le chargeur du disque.
-initrd /home/orel/Documents/projet-qemunet/qemunet/images/debian10.initrd \Charge l’initrd correspondant au noyau.
-append 'root=/dev/sda1 rw net.ifnames=0 console=ttyS0 console=tty0 user=orel ' \Racine sur sda1 en écriture ; noms réseau classiques ; consoles série et vidéo ; « user=orel » dépend de l’image.
-pidfile /tmp/qemunet-orel-OgwDNU/grave.pid \Enregistre le PID du processus QEMU dans un fichier.
-nographicMasque la vidéo QEMU. Sans -serial explicite, raccorde le premier port série et le moniteur à stdin/stdout d’xterm.

Ce qui est implicite : ttyS0 est explicitement demandé au noyau par console=ttyS0 dans -append. QEMU fournit un premier port série virtuel ; -nographic le relie implicitement à stdin/stdout du processus QEMU lancé dans xterm et y partage aussi le moniteur (Ctrl+A, puis C). -nographic ne configure ni console=ttyS0 ni le service getty nécessaire au prompt login:.

Démo web actuelle : lancement type de Debian 13

Exemple KVM · PID et SESSION varient selon l’instance · les chemins sont absolus en exécution

qemu-system-x86_64 \
Option construite par server.jsFonction / remarque
-machine q35 \Choisit explicitement le modèle de machine q35.
-accel kvm \KVM si disponible ; TCG lorsque choisi ou nécessaire.
-cpu host \Expose le CPU de l’hôte en mode KVM ; évite le warning « svm » sur Intel. Absent en TCG.
-m 1024 \1024 Mio pour l’image Debian 13.
-smp 1 \Un processeur virtuel.
-display none \Masque uniquement l’image vidéo QEMU ; ne redirige pas le port série.
-monitor unix:/home/orel/Documents/projet-qemunet/qemuweb/runtime/qemuweb-PID-SESSION.monitor.sock,server=on,wait=off \Socket du moniteur HMP : contrôle de QEMU, indépendant du shell Linux.
-serial unix:/home/orel/Documents/projet-qemunet/qemuweb/runtime/qemuweb-PID-SESSION.sock,server=on,wait=off \Relie ttyS0 au socket ; Node relaie les octets vers xterm.js.
-drive file=/home/orel/Documents/projet-qemunet/qemuweb/runtime/qemuweb-PID-SESSION-debian13-overlay.qcow2,if=virtio,format=qcow2,media=disk \Disque différentiel QCOW2 sur bus virtio ; « disk » explicite ; base RAW préparée.
-boot order=c \Démarre sur le disque, qui charge son propre noyau.
-nic user,restrict=onRéseau QEMU en mode utilisateur restreint ; pas de switch VDE.

Avant ce lancement, qemu-img create -f qcow2 -F raw -b images/debian-13-qemunet-v2-amd64.raw runtime/qemuweb-PID-SESSION-debian13-overlay.qcow2 crée le différentiel. La console ttyS0 et le service de login série sont préparés dans la base RAW. Le navigateur envoie les caractères saisis à Node, qui les transmet au socket QEMU ; la sortie suit le trajet inverse. server=on : QEMU écoute sur chaque socket ; Node se connecte. wait=off : QEMU n’attend pas la connexion pour démarrer.

Le moniteur HMP reçoit des commandes QEMU, distinctes du shell invité : help, info status, info block. system_reset ou quit changent l’état de la VM. L’interface web peut afficher ce moniteur pour la VM QEMU de l’onglet courant ; commandes et réponses sont conservées dans les logs.

Dans les deux méthodes, ttyS0 est configuré côté Linux, et getty fournit le login. Dans l’ancienne commande, seul le raccordement QEMU → stdin/stdout est implicite grâce à -nographic ; la démo utilise un raccordement série explicite vers Node, puis xterm.js.
