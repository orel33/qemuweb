# Session archives (RSD68, format v1)

Use **Save session** in the Web toolbar to download `qemuweb-session-v1.zip`. The dialog shows an estimated compressed ZIP size, source logical bytes and allocated disk bytes, plus an explicit **Include working disks** choice. The final ZIP size can differ from the estimate. Without disks, loading restores configuration, startup files, cabling and the saved browser view, with all machines stopped. The next Play makes fresh working disks from the configured base images. With disks, stop every QEMU host before saving; the next Play resumes each saved QCOW2 overlay. This saves guest disk changes and machine IDs, but never running RAM or process state. VirtualBox working disks are not supported; VirtualBox configuration-only archives use the same v1 format.

Use **Load session ZIP** in an empty session. Import validates the full archive before adding hosts or switches. It verifies the manifest version, file inventory, SHA-256 and ZIP CRC checksums, paths, IDs, names, settings, machine profile, ordered Ethernet connections, ports, MACs, startup files, available disk space and base-image hashes. QCOW2 overlays must pass `qemu-img info` and `qemu-img check`; their backing reference is changed to the local verified RAW base during staging. An invalid or incompatible archive leaves the current session empty and untouched. An existing session must be closed explicitly before loading; import never deletes it.

The archive stores only regular files. It has `manifest.json` and optional `hosts/<id>/startup/...` and `hosts/<id>/disk.qcow2` entries. The manifest has `format: "qemuweb-session"`, `version: 1`, `engine`, `hosts`, `switches`, `baseImages`, `view`, `includesWorkingDisks`, and `files`. Each file record contains a relative `path`, byte `size`, and lowercase SHA-256 digest. Base-image records identify the current RAW or VDI file by format, size and SHA-256; base images themselves are excluded. ZIP v1 stores startup files and streams QCOW2 files through Deflate, so sparse zero ranges compress instead of filling the download. Import verifies the uncompressed bytes and writes only nonzero QCOW2 blocks, then truncates to the original logical length to recreate sparse holes. ZIP64 entry sizes allow a QCOW2 logical size above 4 GiB; the ZIP file itself and its central directory remain limited to 4 GiB. To bound import work, each QCOW2 logical file is limited to 64 GiB and total uncompressed archive contents to 256 GiB. Unsupported ZIP features, symlinks and unsafe paths are rejected. Browsers with the File System Access save picker stream the download to disk; other browsers buffer the ZIP as a Blob before saving, so large archives may need a browser with streaming file save support.

The saved view contains Graphic/Terminals choice, terminal pane count, switch-console visibility, graphic zoom and node positions. Browser-wide naming and font preferences are not part of the archive. Generated ISOs, sockets, PIDs, console output, one-time reset requests and absolute runtime paths are excluded. Startup ISOs and process-specific paths are recreated when restored hosts start. Archives are explicit downloads; normal server shutdown still removes unsaved runtime working disks.

## Verification after test approval

Run `npm test` for archive and existing unit checks. For manual QEMU/KVM validation, create one switch and four Debian 13 Legacy hosts, save/load without disks, then verify startup files, graphic positions, fresh guest disks and all 12 directed LAN4 ping paths. Repeat with working disks after Stop, create a marker inside a guest, and confirm the marker survives Stop/Play after load. Corrupt a file in the ZIP and try a mismatched base image; both loads should fail without creating a host or switch. Repeat the configuration-only path with QEMU/TCG. VirtualBox disk export/import requires a separate compatibility design and check.
