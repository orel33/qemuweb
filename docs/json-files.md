# JSON files of QemuWeb

Specification of the JSON files that QemuWeb reads and writes, and of the
commands the runner builds from `config.json`. It describes the code of this
version; the web interface, the HTTP API and the runner protocol are in the
[user guide](user-guide.md), [reference](reference.md) and [architecture](architecture.md), the installation of a
server in [deployment](deployment.md).

**Conventions.** Flags: **F** fixed once the host exists, **E** editable (host
setting, applied at the next start), **S** a session choice, **G** generated by
QemuWeb (never typed by hand). Braces list allowed values. `†` marks something
that is not implemented. A *node* is a host or a switch. IDs: a host is
`h-` + 16 lowercase hex characters, a switch `s-` + 16, a session 16, a remote
runner `r-` + 8. An unknown keyword is an error in every file below, except where
stated. `schemaVersion` is never migrated: a file with another value is rejected. Every format was at version 1 at the release of 0.9.0; from 0.9.0 on, every format change increments the number and comes with an explicit decision on compatibility (see the decision on `host.json` below: version 2, no migration).

All the JSON files written by the project are UTF-8, indented by two spaces and
end with a newline. `writeJsonAtomic` (`common/json-file.js`) writes a temporary
file (mode 0600) and renames it over the target; `users.json` and `runners.json`
do the same in their own writer.

## 1. Overview of the files

| File | Written by | Mode | ZIP | Read and validated by |
|:--|:--|:--|:--|:--|
| `config.json` (repository root, or `--config`) | user (by hand) | umask | no | `common/system-config.js` (server startup check, every runner) |
| `users.json` (or `--users`) | `scripts/user.sh`, admin API | 0600 | no | `server/auth/users-store.js` |
| `runners.json` (or `--runners`) | server | 0600 | no | `server/runner-store.js` |
| `~/.config/qemuweb-runner/runner.json` (or `--runner-config`) | `runner register` | 0600 | no | `runner/config-file.js` |
| `<session>/session.json` | runner | 0600 | yes | `runner/archive-snapshot.js` (import), `server/server-instance.js` (pruning) |
| `<session>/meta.json` | runner | 0600 | never | `scripts/status.js` (age only) |
| `<host>/host.json` | runner | 0600 | yes | `runner/archive-snapshot.js` (import) |
| `<switch>/switch.json` | runner | 0600 | yes | `runner/archive-snapshot.js` (import) |
| `*.topo` (text, `examples/`) | user, topology export | umask | no | `common/topology.js` |
| session ZIP (`qemuweb-session.zip`) | runner (export) | 0600 | — | `runner/archive-zip.js`, `runner/archive-snapshot.js` |
| `logs/admin.log` (or `--logs DIR`) | server | 0600 | no | `server/audit.js` (tail for `/admin`) |
| `logs/users.log` | server | 0600 | no | `server/audit.js` |

`<session>` stands for `<runtime>/sessions/<id>` (`<runtime>` is `/tmp/qw-<login>/<port>` by default), `<host>` and `<switch>` for `<session>/<node ID>`. The runner
never reads `session.json`, `host.json`, `switch.json` or `meta.json` back to
rebuild a live session: it keeps the state in memory and writes these files so
that they can be archived and inspected. They are read only when a ZIP is loaded
(into a staging directory) and, for `session.json`, to prune the empty sessions a
stopped server left behind. `config.json` is read again at every use (no cache),
so an edit applies to the next operation without restarting anything.

Companions needed to understand the JSON files:

| File | Role |
|:--|:--|
| `.env` (tracked), `.env.local` (ignored) | `NAME=value` lines, executables of the runner (section 3.3). |
| `images/<name>.raw`, `images/<name>.vdi` | Base images named by `image` in `config.json`. |
| `images/<name>.raw.sha256`, `.vdi.sha256` | `sha256sum` format, written by `scripts/prepare.sh`; trusted only while not older than the image (`runner/media/image-hash.js`). |
| `<host>/startup/start.sh` and companions | Startup script and files of a host; in the ZIP when present. |
| `<host>/disk.qcow2`, `disk.vdi`, `startup-<n>.iso`, `*.sock`, `vde/` | Working disks (one per engine), ISO, sockets: never JSON; `disk.qcow2` and `disk.vdi` go in a ZIP, on request. |

## 2. The files

### 2.1 `config.json` — system catalog

Top level: `{"schemaVersion": 1, "systems": {...}}` and nothing else.
`systems.default` is mandatory and abstract (never offered). Every other system
has `"basedOn": "default"` (or another system) and must resolve a non-empty
`image` for both engines. A system ID matches `^[A-Za-z0-9_-]{1,32}$`.

**Inheritance and engine suffixes.** A keyword without suffix applies to both
engines; `keyword:qemu` or `keyword:vbox` applies to that engine only. For each
engine, from the root to the system: the inherited profile is copied, then the
level's common keywords are applied, then its engine variants. So a child's
`memory` overrides a parent's `memory:qemu`, while a child's `memory:qemu`
overrides the child's own `memory`. An unknown keyword, an unknown suffix, an
unknown parent, a cycle, `basedOn` on `default`, or a profile that fails the
checks below is an error (the server and the runner refuse to start).

| Keyword | Values / validation | Default (`systems.default`) | Flag |
|:--|:--|:--|:--|
| `basedOn` | ID of an existing system; forbidden on `default`; no suffix | — | F |
| `type` | `{linux}` | `linux` | F |
| `arch` | `{x86_64}` | `x86_64` | F |
| `mode` | `{text}` | `text` | F |
| `label` | non-empty text | `Default Linux` | F |
| `memory` | integer 64–32768 (MB) | `512` | E |
| `cpus` | integer 1–64 | `1` | E |
| `clock` | `{utc, localtime}` | `utc` | E |
| `startupDiskEnabled` | boolean | `false` | E |
| `serialPorts` | list starting with `ttyS0`, in order, no gap: `[ttyS0]` or `[ttyS0, ttyS1]` (`common/console-id.js`) | `["ttyS0"]` | E (a host keeps a prefix of the list) |
| `firmware` | `{bios}` | `bios` | F |
| `acceleration` | qemu: `{kvm}`; vbox: `{default}` | `kvm:qemu`, `default:vbox` | F |
| `boot` | `{disk}` | `disk` | F |
| `extraOptions:qemu` | exactly 6 strings, three pairs with distinct flags: `-machine q35`, `-cpu host`, `-nic none` (any pair order); `extraOptions:vbox` is rejected | `["-machine","q35","-cpu","host","-nic","none"]` | F |
| `cdromInterface` | `{ide}` | `ide` | F |
| `diskInterface` | qemu: `{ide, virtio}`; vbox: `{sata}` | `virtio:qemu`, `sata:vbox` | F |
| `networkModel` | `{virtio, e1000}` | `virtio` | F |
| `image` | non-empty path, no control character; relative to the project root or absolute; `null` only in `default` | `null` | F |
| `guestAgent` | boolean; says whether the IMAGE of the system contains the guest agent of the engine: `guestAgent:qemu` = `qemu-guest-agent` (channel `org.qemu.guest_agent.0`), `guestAgent:vbox` = VirtualBox Guest Additions. A capability of the image, not a host setting: it is not in Host Settings and never written to `host.json` | `false:qemu`, `false:vbox` | F |

The values of the E keywords are the defaults of a new host; a host stores only
what differs (section 2.5). `serialPorts` only counts for QEMU: the runner
declares `ttyS0` alone for VirtualBox (one `--uart1`). `guestAgent` is
resolved like the others (`guestAgent:<engine>`, then `guestAgent`, then the parent) and every profile
must end with a boolean for each engine; the runner gives it, for the session's engine, as
`guestAgent` in the system list (`GET /api/systems`). Nothing uses it yet (study GAG01, `docs/guest-agent.md`).

Minimal real example (the shipped file has five systems; two shown):

```json
{
  "schemaVersion": 1,
  "systems": {
    "default": {
      "type": "linux", "arch": "x86_64", "mode": "text", "label": "Default Linux",
      "memory": 512, "cpus": 1, "clock": "utc", "startupDiskEnabled": false,
      "serialPorts": ["ttyS0"], "firmware": "bios",
      "acceleration:qemu": "kvm", "acceleration:vbox": "default", "boot": "disk",
      "extraOptions:qemu": ["-machine", "q35", "-cpu", "host", "-nic", "none"],
      "cdromInterface": "ide", "diskInterface:qemu": "virtio",
      "diskInterface:vbox": "sata", "networkModel": "virtio", "image": null,
      "guestAgent:qemu": false, "guestAgent:vbox": false
    },
    "debian13-legacy": {
      "label": "Debian 13 Legacy", "basedOn": "default", "memory": 1024,
      "image:qemu": "images/debian13-legacy.raw",
      "image:vbox": "images/debian13-legacy.vdi",
      "diskInterface:qemu": "ide", "networkModel": "e1000",
      "serialPorts:qemu": ["ttyS0", "ttyS1"],
      "guestAgent:qemu": true
    }
  }
}
```

Lifecycle and warnings: a missing image file is not an error of the file; each
runner announces a warning (`runner/config-warnings.js`) and a remote runner does
not offer the system. Changing the file does not modify existing hosts (section 4).

### 2.2 `users.json`

`{"schemaVersion": 1, "users": [...]}`, sorted by `login` when written. The file
may be absent (no account). With `--no-auth` it is not used. With `--auth proxy` it also lists the
administrators (and any account to disable): a login the authenticating front end gives that is not in the file is a student. Re-read when its
inode, size or date change, so `scripts/user.sh` applies without a restart.

| Keyword (user entry) | Values / validation | Default | Flag |
|:--|:--|:--|:--|
| `login` | `^[A-Za-z0-9][A-Za-z0-9._@-]{0,63}$`, unique | — | F |
| `hash` | `scrypt$N$r$p$<salt b64>$<key b64>`; N a power of two 2–1048576, r 1–32, p 1–16; absent for an account without password (`scripts/user.sh add LOGIN --no-password`): it cannot log in with a password and is only recognised, for its `role` and `disabled`, through the authenticating front end | absent | E |
| `role` | `{student, admin}` | `student` | E |
| `disabled` | boolean; written only when `true`; refuses logins and cookies, and the proxy identity of the login | absent | E |

```json
{
  "schemaVersion": 1,
  "users": [
    {"login": "alice", "hash": "scrypt$16384$8$1$<salt>$<key>", "role": "student"},
    {"login": "bob", "hash": "scrypt$16384$8$1$<salt>$<key>", "role": "student", "disabled": true},
    {"login": "carol", "role": "admin"}
  ]
}
```

Passwords are 1–1024 characters (NFC-normalised before hashing) and never stored.
`users.example.json` is the tracked sample; `users.json` is ignored by Git.

### 2.3 `runners.json`

`{"schemaVersion": 1, "runners": [...]}`: the remote runners registered with this
server. Read once at startup, kept in memory, written through at every change
(the server is the only writer).

| Keyword (runner entry) | Values / validation | Default | Flag |
|:--|:--|:--|:--|
| `id` | `^r-[0-9a-f]{8}$`, unique | generated | G |
| `name` | text, printable, at most 64 characters (the ID when empty) | the ID | E |
| `tokenHash` | 64 lowercase hex: SHA-256 of the authentication token (32 random bytes, base64url); compared in constant time; the token itself is never stored | generated | G |
| `createdAt` | ISO date | registration time | G |
| `lastSeenAt` | ISO date, set when the runner disconnects | absent | G |
| `paused` | boolean, written only when `true`: no new session is placed on it | absent | E |
| `revoked` | boolean, written only when `true`: its token is refused; the record stays until removed | absent | E |

```json
{
  "schemaVersion": 1,
  "runners": [
    {"id": "r-1a2b3c4d", "name": "salle-12", "tokenHash": "<64 hex>",
     "createdAt": "2026-11-02T09:14:00.000Z", "paused": true}
  ]
}
```

### 2.4 `runner.json` — runner file of a remote runner

Written by `./scripts/runner.sh register` (directory mode 0700, file 0600),
read by `run`. It holds the authentication token: never copy it. Unknown keys are
errors. Path: `~/.config/qemuweb-runner/runner.json`, or `--runner-config FILE`.

| Keyword | Values / validation | Default | Flag |
|:--|:--|:--|:--|
| `url` | non-empty text, the server's base URL | — | G |
| `runnerId` | `^r-[0-9a-f]{8}$` | — | G |
| `authToken` | non-empty text, at most 256 characters | — | G |
| `name` | text (may be empty) | — | G |
| `runtime` | optional absolute path of the runtime directory | `--runtime`, else `/tmp/qw-<login>/runner` | E |
| `ca` | optional absolute path of a CA certificate (PEM) | none | E |
| `limits` | optional object, edited by hand | none | E |
| `limits.maxSessions` | positive integer: the server places at most this many sessions | none | E |
| `limits.memoryBytes` | positive integer, lowers the memory announced in hello | machine | E |
| `limits.cpus` | positive integer, lowers the CPU count announced in hello | machine | E |

```json
{
  "url": "https://qemuweb.example.org", "runnerId": "r-1a2b3c4d",
  "authToken": "<token>", "name": "salle-12",
  "limits": {"maxSessions": 4, "memoryBytes": 17179869184, "cpus": 8}
}
```

### 2.5 `<session>/session.json`

The definition of a session; identical to the one in a ZIP. Rewritten at every
creation or deletion of a node, at engine change, and at export. It carries no
owner (a ZIP that adds one is refused).

| Keyword | Values / validation | Default | Flag |
|:--|:--|:--|:--|
| `schemaVersion` | `{1}` | `1` | F |
| `engine` | `{qemu, vbox}` | `qemu` (first engine of the runner) | S |
| `hosts` | unique host IDs, sorted; only hosts with a name and a system | `[]` | G |
| `switches` | unique switch IDs, sorted | `[]` | G |

```json
{
  "schemaVersion": 1,
  "engine": "qemu",
  "hosts": ["h-2b493e734492f941", "h-2ff82cc0d54ff610"],
  "switches": ["s-210a52699538eb60"]
}
```

(Example from `examples/lan.zip`, two of its four hosts.) The engine is the engine of the
session at the time of saving; it can be changed (header select, `session.setEngine`)
while no host of the session is up or busy, and the hosts keep their data: see 2.7. A
loaded ZIP's engine becomes the session engine. A runner that has only one engine uses it.
`schemaVersion` stays 1: this file did not change.

### 2.6 `<session>/meta.json`

What only a live session has. Written by the runner at creation from the values
the server sends; never exported, and a ZIP containing it is refused.

| Keyword | Values / validation | Default | Flag |
|:--|:--|:--|:--|
| `schemaVersion` | `{1}` | `1` | F |
| `owner` | login of the user who owns the session; absent when none | — | G |
| `createdAt` | ISO date | creation time | G |

```json
{"schemaVersion": 1, "owner": "alice", "createdAt": "2026-11-18T08:30:12.123Z"}
```

### 2.7 `<host>/host.json`

**Format decision (VBX02): `schemaVersion` 2, no migration.** The host no longer has an
engine (the engine is the session's and may change), its `config` holds the settings of
both engines, and a ZIP records one base image identity per working disk. The reader
accepts only 2 and refuses 1 like any other version (*Invalid configuration for h-...*); an
`engine`, `disk` or `baseImage` key is an unknown keyword. A session ZIP saved in format 1
is not readable any more: delete it or rewrite its `host.json` files by hand (remove
`engine`, set `schemaVersion` to 2, and in a ZIP with disks replace `baseImage` by
`baseImages`). `examples/*.zip` are rewritten.

| Keyword | Values / validation | Default | Flag |
|:--|:--|:--|:--|
| `schemaVersion` | `{2}` | `2` | F |
| `id` | host ID, equal to its directory name | generated | F |
| `name` | 1–64 characters, no control character, unique in the session (case-insensitive on import) | `h<n>` | E |
| `system` | system ID of `config.json` (not `default`) | — | F |
| `config` | sparse overrides: keys `keyword`, `keyword:qemu` or `keyword:vbox` with `keyword` among `memory`, `cpus`, `clock`, `startupDiskEnabled`, `serialPorts`; each value validated like the catalog (2.1) against the system profile of its engine; an unsuffixed value against the profile of BOTH engines | `{}` | E |
| `config.serialPorts`, `config.serialPorts:<engine>` | prefix of the system's `serialPorts` for that engine (debian13-legacy: `ttyS0` and `ttyS1` under QEMU, `ttyS0` only under VirtualBox, so an unsuffixed list of two ports is refused) | system's | E |
| `network.interfaces` | ordered list of 0–4 entries; the only key of `network` | one disconnected | E |
| `network.interfaces[].switchId` | switch ID of the same session, or `null` | `null` | E |
| `network.interfaces[].port` | integer 1–32 if connected (unique per switch), `null` otherwise | first free | G |
| `network.interfaces[].mac` | `xx:xx:xx:xx:xx:xx` lowercase, unique in the session; `02:` + 5 bytes of SHA-256 of `<id>:<index>` | allocated | G |
| `baseImages` | ZIP only, only for a host saved with working disks: one record per disk of the ZIP, keyed by the format of the base image the disk depends on; the keys are exactly the disks present (`raw` for `disk.qcow2`, `vdi` for `disk.vdi`) | — | G |
| `baseImages.raw`, `baseImages.vdi` | `{size, sha256}` and nothing else: bytes and 64 lowercase hex SHA-256 of the base image file | — | G |

```json
{
  "schemaVersion": 2,
  "id": "h-2ff82cc0d54ff610",
  "name": "grave",
  "system": "debian13-legacy",
  "config": {
    "startupDiskEnabled": true,
    "memory:vbox": 2048,
    "cpus:qemu": 2,
    "serialPorts:qemu": ["ttyS0", "ttyS1"],
    "clock:vbox": "localtime"
  },
  "network": {"interfaces": [
    {"switchId": "s-210a52699538eb60", "port": 4, "mac": "02:a8:8a:35:8d:4c"}
  ]},
  "baseImages": {
    "raw": {"size": 2147483648, "sha256": "<64 hex>"},
    "vdi": {"size": 1879048192, "sha256": "<64 hex>"}
  }
}
```

(`baseImages` only in a ZIP saved with `disk.qcow2` and `disk.vdi`.)

Rules:

- **Resolution for the current engine E:** `keyword:E` if present, else `keyword`, else the
  system profile of E (`config.json`, 2.1). Only the runner resolves; `launchSettings` and
  the startup disk option of a live host are these values.
- **Writing:** Host Settings (and the startup CD-ROM switch) write only the keys of the
  current engine, so editing under VirtualBox never changes the QEMU values and an engine
  switch loses nothing. `keyword:E` is stored only when the value differs from what E
  would resolve to without that key: the profile default, or the unsuffixed value when
  there is one (then the profile default is stored explicitly as `keyword:E`). Unsuffixed
  keys are never written by QemuWeb; they are for files written by hand. Network, name,
  system and the startup files are engine independent.
- There is no profile hash. The identity of a base image is its SHA-256 and size, recorded
  as `baseImages` in the ZIP, and only for hosts that carry working disks (a host without
  disk starts from whatever image is installed).
- A disconnected interface has `"switchId": null, "port": null` but keeps its MAC.
- The disks of a ZIP are the members `<host>/disk.qcow2` and `<host>/disk.vdi`; a
  `disks` key in `host.json` is refused (it is computed from the members).
- Interface changes, hardware changes and the startup-disk option apply at the
  next start, not by hotplug. The editable startup script is not in this file:
  it is `startup/start.sh` (section 2.10).
- The switch of the session engine does not rewrite `host.json`: nothing in it depends on
  the engine.

### 2.8 `<switch>/switch.json`

| Keyword | Values / validation | Default | Flag |
|:--|:--|:--|:--|
| `schemaVersion` | `{1}` | `1` | F |
| `id` | switch ID, equal to its directory name | generated | F |
| `name` | 1–64 characters, no control character, unique among all nodes | `s<n>` | E |
| `kind` | `{vde}` | `vde` | F |

```json
{"schemaVersion": 1, "id": "s-210a52699538eb60", "name": "s1", "kind": "vde"}
```

A switch has at most 32 ports; its VDE directory (`vde/`) and management socket
(`mgmt.sock`) exist only while it runs.

### 2.9 Topology files (`.topo`)

Plain text, not JSON, but they describe the same objects (`common/topology.js`).
At most 256 KB; one directive per line; `#` starts a comment; blank lines are
ignored. Names match `^[A-Za-z][A-Za-z0-9_-]{0,31}$` and are unique,
case-insensitive, across switches and hosts.

| Directive | Syntax | Rules |
|:--|:--|:--|
| `SWITCH` | `SWITCH <name>` | exactly one word |
| `HOST` | `HOST <system> <name> [<switch> ...]` | `<system>` is in `config.json` (not `default`); 0–4 switches, each declared; one interface per switch listed |

At least one switch or host is required; at most 32 interfaces per switch. A
topology is loaded into new nodes (names must not exist in the session, unless
"close previous" is requested): random IDs, default settings of the system,
MAC and ports allocated, default `start.sh`. Export writes the current session
and fails if a host has a disconnected interface. Real file, `examples/lan.topo`:

```text
SWITCH s1
HOST debian13-legacy  immortal s1
HOST debian13-legacy  opeth    s1
HOST debian13-legacy  syl      s1
HOST debian13-legacy  grave    s1
```

### 2.10 Session archive (ZIP)

`qemuweb-session.zip`, UTF-8 names, stored entries (Deflate only for
`disk.qcow2` and `disk.vdi`), data descriptors, ZIP64 sizes when needed. Layout (real
`examples/lan.zip`, one host shown):

```text
session.json
h-2ff82cc0d54ff610/host.json
h-2ff82cc0d54ff610/startup/start.sh        (and companion files)
h-2ff82cc0d54ff610/disk.qcow2              (only "save with working disks", QEMU disk if it exists)
h-2ff82cc0d54ff610/disk.vdi                (same, VirtualBox disk if it exists)
s-210a52699538eb60/switch.json
```

A host may carry both disks whichever engine is current; `disk.vdi` is the VirtualBox
differencing disk. Never in a ZIP: `meta.json`, ISO, sockets, the VirtualBox machine,
RAM, running processes.

What is rejected on load (`runner/archive-zip.js`, `runner/archive-snapshot.js`):

| Check | Rule |
|:--|:--|
| Entry names | only `session.json`, `<id>/host.json` \| `switch.json` \| `disk.qcow2` \| `disk.vdi` \| `startup/<path>`; no `..`, absolute, `\` or control character; no duplicate |
| Structure | single volume; sizes, CRC, local and central headers must agree; no hidden or overlapping entry; no comment, no symbolic link |
| Limits | archive 4 GiB; 10000 entries; metadata files 4 MiB; one working disk 64 GiB; total 256 GiB; 64 MiB free space kept |
| `session.json` | `schemaVersion` 1, only `engine`, `hosts`, `switches`; engine available on this runner; no duplicate ID |
| Node files | `id` equals the directory; `host.json` `schemaVersion` 2 (1 is refused, with no migration), `switch.json` `schemaVersion` 1 with `kind: vde` |
| Hosts | only the keys of 2.7 (`engine`, `disk`, `baseImage` are refused); `system` exists in this `config.json`; `config` keys valid (`keyword`, `keyword:qemu`, `keyword:vbox`), each value valid for the profile of its engine (an unsuffixed one for both); at most 4 interfaces; MACs and (switch, port) unique; a connected interface names a switch of the archive; start script variables resolvable when the startup disk is on |
| Working disks | `baseImages` has exactly one record `{size, sha256}` per disk member (`raw` for `disk.qcow2`, `vdi` for `disk.vdi`), none when there is no disk; each equals the size and SHA-256 of the local base image of that format (a missing local image counts as different), else the whole load is refused, or every disk of the archive is discarded with "Discard working disks" (no partial acceptance). `disk.qcow2` must have a raw backing file and the recorded virtual size, then is rebased and checked; `disk.vdi` must be a differencing VDI (header) of the same disk size whose parent UUID is the local base `.vdi`'s. **A saved VirtualBox disk only loads on a machine whose base `.vdi` is byte-identical**: every conversion to VDI gets a new UUID, so images rebuilt or built elsewhere differ; there is no re-parenting |
| Session | the current session must be empty (HTTP 409 otherwise) |

On success the runner writes its own `session.json` and `host.json` files; the
archive's `session.json` is not copied.

### 2.11 Logs `logs/admin.log` and `logs/users.log`

JSON lines (one object per line), directory mode 0700, files 0600, appended
(`server/audit.js`). A write failure goes to the server's output and never
interrupts the action. Never logged: passwords, typed console text, file
contents, IP addresses; polling and console output are not logged. The `/admin`
page shows the last 200 lines (1–1000).

`admin.log`: `{"time", "admin", "action", "target", "result"}`; `time` is an ISO
date, `result` is `"ok"` or `"error: <message>"`.

| `action` | `target` | When |
|:--|:--|:--|
| `create-account`, `reset-password`, `remove-account` | `{login, role}`, `{login}`, `{login, session}` | admin API on users |

## 3. Translation of `config.json` into commands

The runner resolves `systems[host.system]` for the session engine (inheritance,
suffixes), then applies `host.json.config` on the five editable keywords. `N` is
the zero-based interface index for QEMU, `N+1` for VirtualBox. `—` means no
direct argument. Placeholders such as `<overlay>` are paths under the node's
runtime directory; executables come from `.env` (3.3). The exact command lines of
a host are shown in its Expert tab (`runner/launch-preview.js`) and in its run log.

### 3.1 QEMU/KVM (`runner/engines/qemu.js`, `runner/media/disks.js`)

| Keyword / value | Runner translation |
|:--|:--|
| `basedOn`, `label` | Profile resolution, UI text: no argument |
| `type`, `arch`: `linux`, `x86_64` | Selects `QEMU_SYSTEM_X86_64` |
| `mode: text` | `-display none` |
| `memory` | `-m <memory>` |
| `cpus` | `-smp <cpus>` |
| `clock` | `-rtc base=<utc\|localtime>` |
| `acceleration: kvm` | `-accel kvm` (checks `/dev/kvm`; refused while a VirtualBox host runs) |
| `extraOptions` | six arguments inserted first: `-machine q35 -cpu host -nic none` |
| `firmware: bios` | — (QEMU default BIOS) |
| `boot: disk` | `-boot order=c` |
| `diskInterface` | `-drive file=<overlay>,if=<ide\|virtio>,format=qcow2,media=disk` |
| `image` | `qemu-img create -f qcow2 -F raw -b <image> <overlay>` (first start or reset; Resume keeps the overlay) |
| `startupDiskEnabled: true` | `genisoimage -quiet -R -J -V QWEBSTART -o <iso> <stage>`, then `-drive file=<iso>,if=ide,index=2,media=cdrom,readonly=on,format=raw` |
| `cdromInterface: ide` | the `if=ide` of the startup drive (fixed) |
| `serialPorts` | one `-serial unix:<serialN.sock>,server=on,wait=off` per port, in order: `serial0.sock` is `ttyS0` (COM1), `serial1.sock` is `ttyS1` |
| `networkModel` | `virtio` becomes `virtio-net-pci`, `e1000` stays `e1000` |
| `network.interfaces[N]`, connected | `-netdev vde,id=lanN,sock=<switch>/vde,port=<port> -device <model>,netdev=lanN,mac=<mac>` |
| `network.interfaces[N]`, disconnected | `-device <model>,mac=<mac>` |
| (generated) | `-monitor unix:<mon.sock>,server=on,wait=off` |

Sequence (switches first: `vde_switch -s <vde> -M <mgmt.sock>`, then `vdeterm
mgmt.sock` with `cwd=<switch dir>`):

```text
qemu-img create -f qcow2 -F raw -b <image> <overlay>
genisoimage -quiet -R -J -V QWEBSTART -o <startup-N.iso> <stage>      # if startup disk
qemu-system-x86_64 -machine q35 -cpu host -nic none -accel kvm -display none
  -m <memory> -smp <cpus> -rtc base=<clock>
  -monitor unix:<mon.sock>,server=on,wait=off
  -serial unix:<serial0.sock>,server=on,wait=off
  [-serial unix:<serial1.sock>,server=on,wait=off]                    # ttyS1
  -drive file=<overlay>,if=<diskInterface>,format=qcow2,media=disk -boot order=c
  [-drive file=<iso>,if=ide,index=2,media=cdrom,readonly=on,format=raw]
  [-netdev vde,id=lanN,sock=<vde>,port=<port> -device <model>,netdev=lanN,mac=<mac>]
  [-device <model>,mac=<mac>]                                         # disconnected
```

### 3.2 VirtualBox (`runner/engines/vbox.js`)

The VM name is `qemuweb-<pid>-<session>-<node>`; `controlvm`, `showvminfo`,
`unregistervm` and `closemedium` are also used to stop and clean up.

| Keyword / value | Runner translation |
|:--|:--|
| `type`, `arch` | `createvm --ostype Linux_64 --register` |
| `mode: text` | `startvm --type headless` |
| `memory`, `cpus` | `modifyvm --memory <m> --cpus <c>` |
| `clock` | `modifyvm --rtcuseutc on\|off` (`utc` is `on`) |
| `firmware: bios` | `modifyvm --firmware bios` |
| `acceleration: default` | — |
| `boot: disk` | `modifyvm --boot1 disk --boot2 dvd --boot3 none --boot4 none` |
| `image` (VDI) | `createmedium disk --filename <disk.vdi> --diffparent <image> --format VDI` |
| `diskInterface: sata` | `storagectl --name SATA --add sata --controller IntelAhci`, then `storageattach --port 0 --device 0 --type hdd` |
| `cdromInterface: ide` | `storagectl --name 'Guest setup' --add ide --controller PIIX4`, then ALWAYS `storageattach --storagectl 'Guest setup' --port 1 --device 0 --type dvddrive --medium emptydrive` (or the ISO, see below): the DVD drive exists from the creation of the machine |
| `startupDiskEnabled: true` | `genisoimage` as for QEMU, then the DVD drive holds the ISO: `storageattach --storagectl 'Guest setup' --port 1 --device 0 --type dvddrive --medium <iso>`; at every later start the same command puts the new ISO, or `--medium emptydrive` when the startup disk is off. `--medium none` (a detach) is never used: VirtualBox refuses it on a slot with no drive ("No storage device attached to device slot 0 on port 1 of controller 'Guest setup'") |
| `networkModel` | `--nictype<N> virtio` or `82540EM` (for `e1000`) |
| interface N, connected | `--nic<N> generic --nicgenericdrv<N> VDE --nicproperty<N> network=<vde>[<port>] --macaddress<N> <MAC, uppercase, no colons> --cableconnected<N> on` |
| interface N, disconnected | `--nic<N> null` with the same `--macaddress`, `--cableconnected` |
| absent interface (up to 4) | `--nic<N> none` |
| `serialPorts` | `modifyvm --uart1 0x3F8 4 --uartmode1 server <serial0.sock>` (`ttyS0` only) |
| `extraOptions` | † not defined for VirtualBox |

`ostype` (`Linux_64`), controller names and chip sets are runner constants, not
keywords. The differencing disk `disk.vdi` is created at the first start under VirtualBox,
kept (the machine stays registered) until Reset or the removal of the host, and goes in a
ZIP with the other engine's disk. A `disk.vdi` loaded from a ZIP has no registered machine: the
next start creates the machine around it. VirtualBox resolves the parent of a differencing disk in its
global media registry, and that registry forgets a base image nothing uses (found on a real machine:
"Parent medium with UUID {...} ... is not found in the media registry" after a ZIP load; an
`openmedium` of the base left the registry empty), so the runner first checks the VDI headers (the
parent UUID of the saved disk must be the UUID of the base `.vdi`, else "the saved disk belongs to
another build of the base image"), runs `internalcommands sethduuid` on the saved file inside the node
directory, registers the base the way the first start does (a differencing probe `parent-probe.vdi`
in the node directory, `createmedium --diffparent`), CHECKS with `list hdds` that the base UUID is
registered, then `createvm`/`modifyvm`/`storagectl`/`storageattach` (hard disk and DVD drive) as above (no `createmedium` of the
disk), and closes and removes the probe. On a failure the probe and the machine go and the saved file
stays untouched (Reset starts over). No QEMU monitor exists (`mon.sock`).

### 3.3 `.env` and `.env.local`

One `NAME=value` per line, blank lines and `#` lines ignored, optional quotes
(`runner/preflight.js`). The value is a command name searched in `PATH`
(`^[a-zA-Z0-9_.+-]+$`) or an absolute path. Precedence: non-empty `.env.local`,
then the process environment, then `.env`. `.env.local` is ignored by Git and
never archived.

| Key | Use | Required in `.env` |
|:--|:--|:--|
| `VDE_SWITCH`, `VDETERM` | switch and its terminal | yes |
| `GENISOIMAGE` | startup ISO | yes |
| `NODE`, `PYTHON3` | dependency checks | yes |
| `QEMU_SYSTEM_X86_64`, `QEMU_IMG` | QEMU engine, overlay | yes |
| `VBOXMANAGE` | VirtualBox engine | optional: without it the engine is unavailable |
| `TCPDUMP` | live view of the Capture dialog | optional: without it the live view is unavailable (searched in `PATH`, then `/usr/sbin` and `/sbin`) |

### 3.4 Startup script variables

`startup/start.sh` (at most 64 KiB, UTF-8, no NUL; at most 32 companion files of
1 MiB, 4 MiB in all, relative ASCII paths) is copied into the ISO with:

| Variable | Replaced by |
|:--|:--|
| `@HOSTNAME@` | the host name, shell-quoted |
| `@IFNAME0@` … `@IFNAME3@` | `eth0` … `eth3` |
| `@SWPORT0@` … `@SWPORT3@` | the switch port of that interface (it must be connected) |

An unknown variable, or one for an interface the host does not have, is an error
when the startup disk is on.

## 4. Lifecycle

| Event | Files written or removed |
|:--|:--|
| Session created (first login) | `<runtime>/sessions/<id>/`, `session.json` (empty), `meta.json` |
| Add a host (or topology load) | `<host>/`, `host.json`, `startup/start.sh`; `session.json` |
| Add a switch | `<switch>/`, `switch.json`; `session.json` |
| Edit host settings, cabling, rename | `host.json` (rewritten, atomic); `startup/*` for scripts |
| Change engine | `session.json`; nothing else is written or removed (only while no host is up or busy) |
| Start a host | `disk.qcow2` or `disk.vdi` (first start), `startup-N.iso`, sockets; `host.json` unchanged |
| Stop or Reset | sockets removed; Reset also removes the working disk of the current engine only; JSON unchanged |
| Start a switch | `vde/`, `mgmt.sock`; removed at stop |
| Save session (ZIP) | `session.json` rewritten; the ZIP is built in the session directory and streamed, then removed; with working disks, running nodes are stopped first |
| Load session (ZIP) | staging directory, then `<node>/` directories moved in, `session.json` and node JSON rewritten by the runner |
| Delete a node | its directory, then `session.json` |
| Delete the session | the whole `<runtime>/sessions/<id>/` including `meta.json` |
| Edit `config.json` | nothing is rewritten (see below) |

**What a change of `config.json` does to existing hosts.** The file is re-read at
every operation and no existing file is rewritten by the edit itself.

- `host.json` stores the system ID and the overrides only. At the next save of a
  host, `host.json` is recomputed as the difference between the host's current
  settings and the *new* defaults of its system.
- First start and Reset look the system up again: a new `image` path or hardware
  keyword applies, and a system removed from the catalog fails with "Unknown
  system in config.json". Loading a ZIP that names such a system is refused.
- Resume reuses the system, the engine, the QEMU options captured at the first
  start and the working disk (which only stores differences from the old image);
  only `memory`, `cpus`, `clock` and `serialPorts` are applied again.
- Only a ZIP records the image identity (`baseImages`, for hosts with working
  disks). `.sha256` sidecars let the runner compare it without reading the image.
