Remote runner test sheet

QemuWeb 0.9.0-beta.5.1  ·  one server, one remote runner machine  ·  every command spells out its options (no default relied upon)

What is tested

A runner is the process that runs the machines (QEMU and VDE). Here it runs on another machine, REMOTE, and dials out to the server on SERVER: REMOTE opens no inbound port. The sheet walks through registration with a one-time token, an authenticated connection, a session placed on REMOTE, a real network cut, pause and revocation.

ArrowConnectionCarries
①WebSocket /runner/connect, opened by the runnerThe runner protocol (commands, console streams, state). Authorization: Bearer (runner token) and X-Runner-Id; both ends ping every 15 s. Reconnects by itself.
②POST /api/runner/register, onceThe one-time registration token created in /admin; the answer holds the runner ID and its own token, written to runner.json.
HTTPS, proxy_passBrowsers → nginx → server (variant B)The web interface, Socket.IO consoles. In variant A the browser runs on SERVER itself.

Figure 1. Who connects to whom. The two green arrows cross the network and both start on REMOTE: it needs no inbound port. Variant A carries them through an SSH tunnel, variant B through nginx with HTTPS.

Prerequisites

MachineWhat it needs
SERVERThe repository at ~/qemuweb on main (0.9.0-beta.5.1 or later), npm ci done, an admin account and a student account (./scripts/user.sh list). No local runner for the first test, so that the session can only go to REMOTE.
REMOTEA normal account (never root) in the kvm group; the repository at ~/qemuweb; Node.js 24, npm ci, QEMU with VDE support, vde2, genisoimage, python3; the base images of the systems to test in ~/qemuweb/images/.

Step 0  Start the server SERVER

# variant A
cd ~/qemuweb && git pull
./scripts/server.sh --listen 3002 \
  --runtime ~/qemuweb/runtime \
  --users ~/qemuweb/users.json \
  --runners ~/qemuweb/runners.json \
  --logs ~/qemuweb/logs \
  --session-hours 12 \
  --runner-grace 300

# variant B (behind nginx): the same line plus --trust-proxy loopback
./scripts/server.sh --listen 3002 \
  --runtime ~/qemuweb/runtime \
  --users ~/qemuweb/users.json \
  --runners ~/qemuweb/runners.json \
  --logs ~/qemuweb/logs \
  --session-hours 12 \
  --runner-grace 300 \
  --trust-proxy loopback
Expect: the Options block (every option shown, source option), Checking dependencies…, Checking configuration… with runners.json, then QemuWeb is ready. and No runner connected. (the flags --no-auth and --ephemeral are not used).

Step 1  Prepare REMOTE REMOTE

git clone https://github.com/orel33/qemuweb.git ~/qemuweb && cd ~/qemuweb && npm ci
id -nG | grep -w kvm                          # must answer (else: usermod -aG kvm)
qemu-system-x86_64 -netdev help | grep vde    # must list vde

# images: copy them from SERVER (same files, same hashes), run on SERVER:
rsync -av ~/qemuweb/images/ REMOTE:~/qemuweb/images/
# or build one on REMOTE:  bash scripts/prepare.sh --system alpine
Note: a system whose image is missing on REMOTE is not offered for sessions placed there.

Step 2  Open a path from REMOTE to the server REMOTE

# variant A: keep this terminal open (or run it in tmux)
ssh -N -L 3002:127.0.0.1:3002 USER@SERVER

# check, in another terminal of REMOTE (variant A, then variant B)
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3002/auth/me
curl -s -o /dev/null -w '%{http_code}\n' https://qemuweb.example.org/auth/me
Expect: 401 (or 200): the server answers. Variant B with a private authority: curl --cacert ~/ca.pem ….

Step 3  Create the registration token BROWSER

Open the server, sign in as admin, go to /admin → Runners and create a registration token (1 hour is enough). The page shows the command once: copy the token. It is single use and expires.

Step 4  Register REMOTE REMOTE

# variant A
./scripts/runner.sh register --url http://127.0.0.1:3002 \
  --token TOKEN \
  --name salle-test \
  --runtime ~/qemuweb/runtime \
  --runner-config ~/.config/qemuweb-runner/runner.json

# variant B (add --ca ~/ca.pem only for a private certificate authority)
./scripts/runner.sh register --url https://qemuweb.example.org \
  --token TOKEN \
  --name salle-test \
  --runtime ~/qemuweb/runtime \
  --runner-config ~/.config/qemuweb-runner/runner.json

ls -ld ~/.config/qemuweb-runner ~/.config/qemuweb-runner/runner.json
Expect: the runner file exists, directory drwx------, file -rw-------. Running the same register again with the same token must be refused (single use).

Step 5  Run the remote runner REMOTE

# variant A
./scripts/runner.sh run \
  --runner-config ~/.config/qemuweb-runner/runner.json \
  --runtime ~/qemuweb/runtime \
  --config ~/qemuweb/config.json \
  --url http://127.0.0.1:3002

# variant B
./scripts/runner.sh run \
  --runner-config ~/.config/qemuweb-runner/runner.json \
  --runtime ~/qemuweb/runtime \
  --config ~/qemuweb/config.json \
  --url https://qemuweb.example.org
Expect, on REMOTE: the banner, Options, Checking dependencies… (QEMU, VDE…), Checking configuration…, then Connected to the server. On SERVER: a line for the connection of salle-test; /admin → Runners shows it as remote, online, with engines, systems (installed images only) and warnings. Keep this terminal open (tmux).

Step 6  Place a session on REMOTE BROWSER

In a second browser profile sign in as toto, add a switch and a host, start both and open the console. Then check where the machines run:

# on REMOTE: the QEMU and vde_switch processes are here
ps -eo pid,args | grep -E "qemu-system|vde_switch" | grep -v grep | cut -c1-110
# on SERVER: nothing
pgrep -a qemu-system
Expect: machines on REMOTE only; in /admin the sessions counter of salle-test is 1.

Step 7  Cut the network for real REMOTE

# variant A: kill the tunnel
pkill -f "ssh -N -L 3002:127.0.0.1:3002"
# variant B: drop outgoing HTTPS
sudo iptables -A OUTPUT -p tcp --dport 443 -j DROP

# wait 30 to 45 seconds, then restore (A: open the tunnel again; B: remove the rule)
ssh -N -L 3002:127.0.0.1:3002 USER@SERVER
sudo iptables -D OUTPUT -p tcp --dport 443 -j DROP
During the cut: /admin shows salle-test offline; toto's page says "Runner offline, reconnecting…" and its requests answer 503; on REMOTE ps still lists the same machines. After: the runner reconnects by itself (2, 4, 8, 16, then 30 s), the page resynchronises and the same machines answer. The grace period is 300 s (--runner-grace 300); after it the sessions are dropped.

Step 8  Pause and revoke BROWSER

  1. Pause salle-test in /admin → Runners: a new user gets no session (No runner is available), toto's session goes on. Then Resume.
  2. Revoke: the runner stops its machines and exits with status 1 and does not reconnect. Check on REMOTE: no QEMU left under ~/qemuweb/runtime. Then Remove.
  3. On SERVER: tail -n 20 ~/qemuweb/logs/admin.log lists every action, never a token.

Clean up

# REMOTE: Ctrl+C in the runner terminal (it stops its machines), then
rm -f ~/.config/qemuweb-runner/runner.json
# SERVER: Ctrl+C in the server terminal, then if anything is left
./scripts/stop.sh --listen 3002 --runtime ~/qemuweb/runtime
./scripts/killall.sh

Troubleshooting

SymptomCause and fix
register fails, token refusedUsed or expired token: create a new one in /admin → Runners. Check the URL answers (Step 2).
run exits at once with status 1The server refused the token (runner revoked or removed): register again with a new token.
409 on connectionThat runner is already connected from another process: stop the other one.
"No runner is available" for a userThe runner is paused, offline, or at its maxSessions; the server log gives the reasons.
A system is missing in the Add host dialogIts image is not installed on REMOTE (Step 1).
A plain http:// URL is refusedOnly loopback is accepted without --insecure; use variant A or https://.
Sessions gone after restarting the serverKnown limit: a server restart deletes the sessions of a remote runner (see docs/todo.md).

Remote runners are for trusted machines until milestone 6 (jail, quotas, HMP allowlist): a runner runs the machines under the account that starts it, with no confinement.
